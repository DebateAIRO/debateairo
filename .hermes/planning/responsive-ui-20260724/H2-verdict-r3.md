Canvas-only `touch-action:none`, custom `scrollLeft/scrollTop` pan, Chromium two-pointer PE, WebKit GestureEvents, and a touch-event fallback are plausible platform mechanisms. Page pinch remains unrestricted outside `.canvas`, and custom pan does not alter the transformed card's layout box; the existing measurement really is `offsetHeight` (`DebateCanvas.tsx:94-109`), so the sizer/inner-transform model can preserve that invariant.

   The iOS delivery contract is nevertheless incomplete at the exact hard seam. `GestureEvent` exposes `scale`/`rotation` and inherits `UIEvent`; it does not supply the two-touch centroid used by the focal-preservation formula (MDN: `https://developer.mozilla.org/en-US/docs/Web/API/GestureEvent`). The plan disables the PE two-pointer path when GestureEvents are active but never names an alternate centroid source (for example, concurrent TouchEvent touch coordinates), nor does `gesturestart` explicitly suspend/terminate the already-active one-pointer PE pan. Thus §b.2 promises focal preservation on iOS without defining the data or event-ownership transition that makes it possible (`Plan.md:130,133-136`). This is a hard-requirement design gap, not polish.

   Custom pan also begins on the first `pointerdown` anywhere in `.canvas` with no movement threshold, interactive-target arbitration, or post-drag click suppression (`Plan.md:133-136`). The current canvas contains a sticky checkbox and clickable cards/buttons (`DebateCanvas.tsx:121-147,268-281,387-420`). The implementation contract must preserve taps and controls while still allowing a second pointer to promote the gesture to pinch. Momentum/rubber-banding loss is honestly declared a non-goal and is not a blocker. Keyboard-scroll wording should be made testable by requiring a focusable canvas/viewport; `touch-action` alone does not guarantee keyboard focus. The offsetHeight gate is sound provided overview simplification hides content without collapsing card layout; the stated constant-offsetHeight Playwright assertion will enforce that.

## New findings

### NEW-5 — HIGH — iOS pinch lacks a defined focal-coordinate and event-ownership contract

- **Evidence:** `Plan.md:130,133-136` drives Safari zoom from `GestureEvent.scale`, promises focal preservation, disables the PE two-pointer path, and does not define where the two-touch centroid comes from or how `gesturestart` stops the current one-pointer PE pan. MDN documents `scale` and `rotation`, not touch points/centroid. The same state machine starts panning on the first pointer without an interactive-target/drag-threshold policy, despite live checkbox/card/button descendants in `DebateCanvas.tsx:121-147,268-281,387-420`.
- **Severity/rationale:** HIGH because iOS pinch and existing canvas actions are mission-completion capabilities. Hard real-device gates will detect failure, but a gate is not a delivery design.
- **Required correction:** Pin the Safari event composition: source centroid coordinates explicitly (or define a truthful alternative focal policy), suspend PE pan atomically on `gesturestart`, prevent double mutation, and define first-pointer drag threshold/interactive-target/click-suppression behavior while allowing promotion to two-finger pinch. Add handler-contract tests for those transitions plus the existing real-device proof.

### NEW-6 — MEDIUM — the collapsed synthesis tab still intersects the expanded token dock

- **Evidence:** `Plan.md:175-195` gives the dock up to 360px width but subtracts only the 52px zoom-column reservation from the centered synthesis tab. Computed overlap is 180px at 320px and 308px at 568px. Both are bottom chrome, and no disjoint vertical band is defined.
- **Severity/rationale:** MEDIUM because it breaks the explicit reserved-rectangle invariant and makes the owning-slice collision gate unsatisfiable, but it is locally redesignable without changing mission architecture.
- **Required correction:** Give the collapsed tab a rectangle disjoint from the dock's expanded width and vertical band at every required cell (for example, a specified stacked band or mutually exclusive/collapsed state), then retain the S5 and S8 geometry assertions. Also define the short-height compact arrangement for the four ≥44px zoom buttons above the 96px dock cap rather than relying on the matrix to discover clipping.
