# tests/ci-integration-auth.txt — the sign-in / account-security integration suites CI runs on every change.
#
# Gate: `pnpm run test:ci-integration` (tools/ci-known-red.mjs @tests/ci-integration-auth.txt), the CI job
# "auth-integration" in .github/workflows/security.yml. Each file starts its own embedded PostgreSQL
# (tests/support/testDatabase.ts; ubuntu installs @embedded-postgres/linux-x64) and runs the real migrations, so
# these are the only checks that prove, against SQL, the rules the unit suites can only fake: the server-side resend
# limit, the 30-day absolute session cut-off, phone masking and recovery-email lifecycle in storage, reset and
# MFA-recovery non-enumeration, the staff boundary and the upgrade path. Files run one at a time
# (vitest.config.ts fileParallelism: false). Failures are judged against tests/ci-known-red.txt like the unit gate;
# host-sensitive cases (timing / memory tripwires) are reported but never gate, via tests/ci-flaky.txt.
#
# A file is listed only when it needs nothing outside the repository (no Docker, network, provider keys or host
# services). Each was run alone on 2026-10-09 (branch fix/2026-10-09-real-auth-tests) and passed; the gate over the
# whole list took about five minutes on the Mac (2-35 s per file).
#
# One path per line, product-relative. A path that does not exist fails the gate (no silent shrinking).
