## Addendum to V-11 — prompt-injection safeguards and the editable-prompts foundation

**Ruled 2026-09-22 (V, chat): "yes to both".** V had asked for more safeguards than the original containment fix, and had stated a standing product requirement (owner-editable prompts, per step, at any time, under the owners' rules — AI-written prompts included). The agent proposed the following; V approved it as proposed.

**Premise, verified in code that day.** The development relays launch every vendor CLI with tools disabled (`acceptance/claude-relay.ts`: `--tools ""`, `--safe-mode`, `--strict-mcp-config`, `--no-session-persistence`; `acceptance/grok-relay.ts`: `--tools ""`, `--sandbox`, `--no-memory`, `--no-subagents`, `--disable-web-search`; `acceptance/hermes-relay.ts`: `--toolsets context_engine`, `--ignore-user-config`, `--ignore-rules` — the `context_engine` toolset is to be confirmed harmless in RUN1). So an injection can change what a model SAYS, not what it can DO; the safeguards protect the truth of verdicts.

| # | Layer | When |
|---|---|---|
| 1 | Separate compartments: engine instructions and model-written text never share a block, at EVERY hand-off (the judge legs, the expansion legs, the synthesizer digest, the evaluator packet, the repair packets) | **now — RUN1** |
| 2 | Unforgeable fences: a fresh random boundary marker per call, so model text cannot forge an end-of-material frame | **now — RUN1** |
| 3 | Locked answer forms: strict schemas (closed choices, ranged numbers) validated in code; repair and error paths never echo model text | **now — RUN1** |
| 4 | A permanent injection test-suite in CI (English and Romanian: overrides, fake system messages, fence forgery, role-play, hidden/encoded text) proving structurally that attack text always lands inside the evidence compartment; no model calls | **now — RUN1** |
| 5 | Tripwires: a per-call canary the model must never repeat (its appearance flags the step) and a light scan for instruction-like phrases — signals, not gates | **now — RUN1** |
| 6 | Measured resistance: the attack suite against real models, producing a per-model attack-success rate tracked over time | later — costs model usage; V runs it |
| 7 | Swap check for published debates: judge twice with positions swapped; a flipped verdict is flagged | later — doubles judge cost for those debates; V decides with numbers |
| 8 | A human look before a flagged debate reaches the public library | later — product decision |

Cost of layers 1–5: about one agent-day on top of RUN1's one to two.

**Editable prompts — the foundation is laid now, the feature is its own design conversation after the decisions.** Verified that day: prompts are source-code constants pinned by hash in the register, so an edit is a code change today. Approved principle: every step's prompt splits into (1) a SAFETY FRAME OWNED BY CODE — the fences, the untrusted-material sentence, the required answer form — that no editor, human or AI, can remove, and (2) the OWNERS' INSTRUCTION TEXT, editable per step. Approved rules, enforced by code rather than trust: every edit is a new sealed version (who, when, what changed; instant rollback) — never an edit in place; a rules gate runs before a version can go live, identical for human-written and AI-written prompts (passes the injection suite, keeps the required answer form, length limits, optional preview on fixed sample debates showing how verdicts move); only owner accounts activate, and every activation is logged. RUN1 builds the containment ON the frame/instruction split. Where prompts are edited (admin page, command, files), who may edit, and whether a second approver is required are for the feature's own design conversation.
