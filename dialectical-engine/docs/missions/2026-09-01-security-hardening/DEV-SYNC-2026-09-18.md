### 2.1 The admission row and `dev`'s sealed register history (corrected during the sync)
`dev`'s register-publication port seals the historical bootstrap set by snapshot hash (14 rows, `LEGACY_REGISTER_V1_SNAPSHOT_SHA256`) and publishes everything newer as a fresh, allocator-numbered version. At `b5a6b6eb` this branch had added `admissionPolicy` to the bootstrap set (`+ 5`). Under the new model that is wrong twice over: it would change the pinned legacy hash, and the bootstrap builder takes canonical ASTs, not plain numbers (`CANONICAL_REGISTER_JSON_AST_INVALID`).
**Resolution:** the row is a DEPLOYMENT row only (`developmentRows`, where `developmentValueAst` canonicalises it); `packages/register/src/index.ts` now differs from `dev` only by this branch's exports. Pins updated: `b10-admission-policy-register.test.ts` (asserts the row is absent from the historical builder and present in the dev seed), `register-support-publication.test.ts` (49 → 50 rows, and 49 again with `admissionPolicy` removed).
**Carry to deployment:** the production register publication must contain `admissionPolicy`, or API boot refuses with `ADMISSION_POLICY_UNRESOLVED` (fail-closed by design).
