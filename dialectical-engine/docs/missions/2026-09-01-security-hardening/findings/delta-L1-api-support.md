## Verified-OK controls
- **No cross-session read/rate/escalate (no IDOR).** Every `sessions/:id/*` route requires the `x-support-session-token` whose sha256 must equal the row's `session_token_sha256` (`WHERE session_id=$1 AND session_token_sha256=$2`, `packages/db/src/support.ts:430-445,494-511,676-690`) **and** `sessionOwnerMatches` (`support/index.ts:91-93`) — an owner-bound session needs the token *and* the matching owner cookie; an anon session needs the token *and* an anon request. Rating joins message→session under the same token and `message.session_id=body.session_id` (`support.ts:676-698`). Token is 256-bit random (`randomBytes(32).toString("base64url")`, `support/session.ts:569-579`).
- **Own-context reads are ownership-gated in SQL and never trust the message body for identity.** `read_own_run_state` runs `core.run_is_owned_by(run, ownerRef, legacyAskerId)` with `ownerRef` taken from `request.authenticatedSession.ownerRef`, never from `run_id`/message (`support/own-context.ts:104-131`; `packages/db/src/support.ts:95-187`). A crafted `run_id` for another user returns `NOT_OWNED` → `REFUSE_OTHER_USER`.
- **Consent gate precedes any own-context DB read.** A message reaches `read_own_run_state` only when `authenticatedSession !== undefined` **and** `consent_own_context_at !== null`; otherwise `ANON_CONTEXT`/`CONSENT_NEEDED` is returned first (`support/index.ts:466-495`). The model relay itself is corpus-only and needs no consent (by design).
- **Injection lock.** REFUSE_INJECTION writes an `abuse_event` and, at `lockAfterInjections`, transitions the session to LOCKED (dynamically in `read`, and via `finalizeInjectionLock`) (`support/index.ts:446-452,707-713`; `packages/db/src/support.ts:432-444,516-518,628-643`). Per-session (attacker can open a new session) — an abuse control, not a boundary; correctly scoped.
- **Model spend is bounded and the relay is loopback-pinned.** Every model path goes through the durable per-UTC-day cap (`reserveModelCall`, `packages/db/src/support.ts:1698-1746`) and the reserved single-use port (`support/model-reservation.ts:235-289`); `RelayAdapter` refuses any non-`http://127.0.0.1:.../v1` target and any non-`Bearer` header (`support/model.ts:62-100,160-190`), caps the response at 256 KiB / 16 000 code points, and treats `finish_reason==="length"` as a distinct failure (W10) rather than serving a truncated answer.
- **Malicious model output (A3) is contained.** Server-authored `Source:` lines are stripped, output is redacted before persistence/transit, and the model cannot influence the case token or ownership (`support/answer.ts:113-115,223-243`).
- **Support KEK loader is hardened and domain-separated.** O_NOFOLLOW + uid + nlink==1 + mode 0600 + size==32 on the file, parent dir 0700/same-uid, and refusal if the support KEK equals any protected key by path/inode/bytes (`support/keys.ts:244-308,537-560`). AEAD envelopes are length-prefixed and context-bound (`:136-201`).
- **Shred is operator-only and idempotent.** No HTTP route reaches shred; `shredOwner/shredSession` are transaction-bound with advisory locks, re-run returns `ALREADY_SHREDDED`, and a global integrity guard trigger backs it (`packages/db/src/support.ts:1432-1512`; `migrations/0054`).
- **Authenticated support mutations are CSRF/Origin-protected.** When a support session request carries an authenticated cookie, the preHandler enforces exact Origin + double-submit CSRF + `verifyCsrf` (`apps/api/src/index.ts:1453-1459`) — the branch's B-series stack applies unchanged.
- **Capability-header grammar/length is validated at the API.** `x-support-session-token` is forwarded verbatim by the proxy (allow-listed, `apps/ui/app/api/[...path]/route.ts:23`) and validated by `hashSupportCapability`'s `^[A-Za-z0-9_-]{43}$` (`support/session.ts:9,564-567`); an over-long or malformed header → 404 (probe P8). Bodies inherit the 256 KiB `bodyLimit` and the constant `MALFORMED_REQUEST` envelope (`index.ts:1343-1361`).
- **Delta on the audited auth routes is safe.** `recovery.ts`/`sessions.ts` only widen the risk-signal-failure callback to receive the error, routed through the output-alphabet-bounded `riskSignalFailureIdentity`/`authenticationRiskSignalPoisonCategory` (no cause text reaches logs); `startup-resource-owner.ts` binds pre-listen resources to graceful shutdown; `account-erasure.ts` adds bounded `diagnosticStage` labels only; `publications.ts` adds a derived `models[]` list to public debate rows (deduped model_ids, no new secret). None weakens a baseline control.

## Out-of-scope observations
- L5/DB: `support.message` and `support.session` have **no index** on `session_id` (only PK + FK); `PostgresSupportMessageRepository.listSession` and the case-open snapshot do full scans as volume grows — perf, not security, but it compounds DL1-F2's `/status` cost.
- L5/schema: `hashSupportCapability` is an **unkeyed** sha256 shared by session and case tokens (`support/session.ts:564-567`) — acceptable because tokens are 256-bit random and compared as hashes, but the same B19 (INFO) observation as the main token store applies.
- Owner/V: the anon message POST accepting `content-type: text/plain` (Fastify default parser) is harmless (parses to a non-object → `{}`), but removing the `text/plain` parser on `/v1/support/*` would tighten the surface.
- L4/live-mission: `contract` now closes `depth_params` to `{depth: 1..5}` and widens `served_root_rule` to the rule *history* — both reviewed, no consumer switches on the field; noted only as context for the runner delta.

## Confidence and residuals
- **Not run against a live DB.** DL1-F1/F3/F4 were reproduced in-process with fake ports that emulate the `uuid`-column `22P02` behaviour; the SQL column types are read directly from `migrations/0050`/`0054` and `packages/db/src/support.ts`, so the 22P02→500 path is a line-by-line trace confirmed by the probe. A focused `vitest run tests/integration/support-routes.test.ts` on the quiet-host window would harden DL1-F1/F5/F6 to reproduction-on-real-Postgres.
- **DL1-F6 is PLAUSIBLE by design intent**, not defect: erasure-vs-support decoupling may be the ruled retention model. It needs a V decision, not a code fix, unless erasure must cascade.
- **What would change severities.** If V rules the product stays loopback-only, the anon-facing DoS/disclosure findings (F2, F4, F7) drop toward LOW. If a UUID schema lands on the support `{id}` params, F1 closes. If `/status` is trimmed to the widget fields, F4 closes. F5 stays MEDIUM until case tokens expire or bind to the owner; the token strength itself is sound, so the risk is entirely leakage-driven. No finding rises to HIGH/CRITICAL: model spend is globally capped, tokens are 256-bit, ownership is SQL-enforced, all queries are parameterized, and the KEK loader is hardened — I found no unauthenticated path to identity material, keys, another user's private content, or unbounded spend.

### What each fix does
- **DL1-F1** — the five `{id}` support routes and the rating body's `session_id` are matched against a mirror of the API's `ResourceIdSchema` (`SUPPORT_RESOURCE_ID`) before any repository call and answer the branch's constant `{error:"NOT_FOUND",message:"NOT_FOUND"}`. The test counts zero `read`/`rateMessage`/`setConsent` calls and zero `api.request.failed` lines.
- **DL1-F3** — a backward observation refuses only the call that carried it, emits exactly one `{"event":"support.admission.clock_regression","skew_ms":N}` line, keeps the high-water mark (so the refused call records nothing and resets nothing), and the next forward observation is admitted. A session row dated ahead of the clock likewise refuses only its own call. An unusable timestamp (NaN, infinite, negative, unsafe) still latches closed. The per-source window logic is untouched.
- **DL1-F4** — the anonymous body is now exactly `configuration.kind`, `relay_state`, `kb_version`, `kb_loaded.shipped`. No new HTTP route: the full operator view already lives in `apps/runner/src/support-status-cli.ts`, which reads the database directly. `packages/contract` carries no response schema for this route, so nothing shrank there, and `apps/ui/components/support/Assistant.tsx` reads only fields that remain.
- **DL1-F9** — `body.text` over 16 KiB of UTF-8 (`SUPPORT_MESSAGE_BYTE_CEILING`) takes the constant 400 `MALFORMED_REQUEST` envelope before the session read, the configuration read, the sha256 and the classifier; a body at the ceiling still reaches the register-driven 2 000-code-point rule and its RATE_LIMITED evidence.
- **DL1-F8** — the ledger keeps a fixed window of the newest 64 records (`SUPPORT_MODEL_RESERVATION_EVENT_CAP`) instead of one per model call forever; `events()` still answers in order for the seven assertions that use it, and the `#active` set the release path depends on is unchanged.
- **DL1-F5 (a+b)** — one gate in the case-access service refuses a token whose case is older than `SUPPORT_CASE_TOKEN_TTL_MS` (30 days, from the `created_at` already on the row — no migration) and, when the case carries an `identity_owner_ref`, a caller that is not that authenticated owner. Both refusals are the unknown-token 404, never a 403. The routes pass the observation instant and `request.authenticatedSession`; a caller the route does not declare is read as anonymous, so the gate fails closed.
