## Required invariant

- Every live relay instance owns a fresh high-entropy credential generated by the server.
- `/v1/chat/completions` rejects missing, wrong, duplicated/alternate-shape, and other-relay credentials before body retention, parsing, or child spawn.
- Credential comparison has fixed-size inputs at the timing-sensitive comparison.
- All trusted acceptance callers send the credential only as the Authorization header.
- The credential is never copied into model messages, CLI argv, child environment, or logs.
- A credential from one relay instance cannot authenticate to another.

## Implementation

- `startCliRelayServer` generates `Bearer ${randomBytes(32).toString("base64url")}` once per server and retains only its SHA-256 digest in the request closure.
- `singleAuthorizationHeader` scans `rawHeaders`, requires exactly one Authorization field, and maps missing or duplicate fields to an empty candidate.
- `authorizationMatches` hashes every candidate to 32 bytes and applies `timingSafeEqual` against the stored 32-byte digest.
- Authentication runs immediately after the exact method/path check and before `readBody`; denial is the fixed `401 { error: "UNAUTHORIZED" }` response.
- `CliRelayHandle.authorizationHeader` is explicitly threaded through model-shim, Claude, Grok, acceptance runtime, discovery, dual-maker proof, and ceremony call sites.
- The standalone catch-up process reads an exact provider-ref map from `RELAY_AUTHORIZATION_HEADERS_JSON`; credentials stay out of CLI argv and are supplied only to the gateway/probe Authorization header.
