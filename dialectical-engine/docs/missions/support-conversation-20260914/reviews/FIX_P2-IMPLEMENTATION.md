# FIX_P2 implementation design

Revision `f4402871` implements the reviewed-recovery architecture from SPEC-v3 and PLAN_P2. It adds one exact, ordered component record for every shipped article/language. Each record binds the exact article digest to a bounded model projection and deterministic visitor fallback. The component file intentionally contains no editorial identity or owner ratification.

The loader parses exact component and manifest-v2 schemas, validates semantic safety and complete corpus membership, binds every article/projection/fallback/file digest to a separate review record, and incorporates those bytes and review facts into `kbVersion`. Strict API and status-CLI callers require every recovery record to be reviewed. The committed manifest remains schema v1, so production strict startup is intentionally blocked until EDIT_P2 supplies a real review and ATTEST_P2 writes the matching manifest-v2 evidence. Non-strict component loading excludes unreviewed recovery records from the returned snapshot.

Model context is assembled only from admitted projections. It preserves complete sections under the 24,000-code-point cap and does not serialize article titles, raw bodies, routes, repository paths, or canonical IDs. A request resolves one immutable snapshot before model work. After exactly one existing-model completion, any rejected ordinary-knowledge envelope or policy result is discarded. The server may return only the screened fallback of the pinned top source, with that canonical source and the intersection of its catalog actions and the request-local available actions. Case summaries and requests with no admitted fallback retain their existing outcomes.

The shared kernel now owns complete supplied credential-value spans, separates later positive modal clauses from earlier negation, recognizes explicit noncredential account/profile/display-name objects, and recognizes root, relative, drive, UNC, and encoded path forms. The response, context, recovery, case-summary, redaction, storage, and HTTP sinks reuse those shared predicates. No rejected completion text or arrays contribute to recovery provenance.

The author tests cover exact schema, missing/stale/tampered review evidence, immutable snapshot version changes, projection-only context, complete-section packing, fallback choice, usage/cipher/HTTP preservation, rating and metrics effects, EN/RO credential boundaries, 52 current human labels, canonical paths, and neighboring benign controls. Restored mutants prove the tests reject raw-body context, disabled recovery, and disabled canonical-path screening. LIVE_P2 owns the unchanged final 25-file integrated union after ATTEST_P2; this author stage does not claim preview or checkpoint readiness.
