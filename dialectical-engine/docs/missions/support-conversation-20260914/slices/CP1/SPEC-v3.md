## Objective

A visitor can use the established Support widget or `/help` surface in English or Romanian to get current, peer-reviewed product facts and safe first-party navigation. The server treats model text as untrusted, screens every completion before storage or HTTP, and keeps all account authority outside Support.

## Terms

- **Peer-reviewed** means a named reviewer has produced a durable review artifact for the exact EN/RO content revision. It does not mean owner-ratified.
- **Owner-ratified** means V has explicitly accepted the checkpoint and the paired `ratified_by` / `ratified_on` fields record that real event. Blank fields mean no ratification.
- **Canonical reply** is the final server-authored or server-validated text plus server-resolved sources and actions. The same canonical text is encrypted and returned over HTTP.
- **Action** is a closed catalog identifier resolved by server code using trusted request context. Model text and user text never supply an `href`.

## Functional requirements

### Catalog and navigation

- **CP1-R01 — Complete route disposition.** The catalog accounts for all 11 current `apps/ui/app/**/page.tsx` routes identified by the approved product map. `/verify-email`, `/enroll-mfa`, and `/admin/workers` are known but ineligible for ordinary model-generated actions. `/api/[...path]` is recorded as a proxy, not a page action.
- **CP1-R02 — One browser-safe catalog.** `@debateai/support-kb` exposes a browser-safe subpath containing the capability records, bilingual action labels, and the closed action-id union. The Node filesystem loader remains outside that subpath. API and UI action validation consume this catalog rather than maintaining new duplicate route arrays.
- **CP1-R03 — Closed resolver.** `resolveSupportActions(ids, context)` drops unknown, inapplicable, external, protocol-relative, backslash, token-bearing, missing-fragment, and unverified dynamic destinations. `signedIn=true` alone never authorizes an owner debate link. Owner run IDs and public references come only from trusted, previously verified projections.
- **CP1-R04 — Accurate current links.** Static actions may resolve only to verified current destinations. `/settings#consent-privacy-heading` is valid; `/settings#privacy`, `/settings#cookies`, invented `/privacy` and `/terms` routes, and the placeholder pricing anchor are not offered as working destinations. Cookie/privacy modal controls may be actions only when the existing opener is callable through a reviewed first-party adapter.
- **CP1-R05 — Forgot password dependency.** `forgot-password` exists in the action union because the owner confirms the feature. It resolves to no action until the exact existing URL or UI opener is verified in the target app. CP1 completion requires recording that destination, an action-resolver test, and a UI click test. The implementation must not create a replacement, use Settings, substitute saved-MFA recovery, or default to human escalation.
- **CP1-R06 — Deterministic recovery intent.** Before the generic password/account refusal classifier, deterministic EN/RO matching recognizes at least `Forgot password`, `I forgot my password`, `Can't remember my password`, `Am uitat parola`, and a mixed request for a replacement password. It returns concise guidance and the verified `forgot-password` action without calling recovery APIs or the model.

### Knowledge and provenance

- **CP1-R07 — Current bilingual facts.** Every shipped capability in the catalog maps to at least one complete EN/RO article pair. Corrections cover actual debate creation, Free/Premium controls, navigation, public/private access, JSON export, local-only or unavailable actions, account/session controls, privacy/consent, support cases, status limitations, and the current 48-hour case SLA.
- **CP1-R08 — Review provenance.** Preserve exact article provenance and require separate Sol editorial identity/evidence plus exact hashes for all new model projections and visitor fallbacks. Do not inherit owner ratification for new component bytes, self-attest, or invent reviewers. Eligible new components remain peer-reviewed preview content until explicit owner acceptance.
- **CP1-R09 — Honest preview gate.** Every shipped entry/language requires admitted complete factual projection and a separately reviewed fallback before their preview use. Missing/stale/mismatched component review evidence fails closed. Validate all actual corpus entries, including legacy/in-code sources. Preserve distinct preview/owner-ratified counts and exclude new unratified components from production release.
- **CP1-R10 — Session-pinned snapshot.** kbVersion binds eligible article, model-projection, fallback, catalog and selecting review bytes. Session creation stores that exact immutable version. Matching available A is used through selection, model work, recovery and persistence; unavailable A returns the existing zero-write409 restart response before model/persistence. Browser creates B and retries the current already-redacted request at most once, never mixing A/B or looping.
- **CP1-R11 — Reachable knowledge.** Reviewed sources remain lexically reachable without INTENT_SIGNALS edits. Model context uses only complete admitted factual projections, titles and capability/policy labels, never implicit raw article bodies. No canonical source/action/capability ID, catalog route or repository metadata enters model-facing surfaces. Preserve whole sections and the exact24,000-code-point composed system cap.
- **CP1-R12 — Visitor-safe sources.** HTTP and UI source objects contain reviewed IDs and visitor labels only. Repository paths, `verified_against`, reviewer identities, evidence paths, prompt policy, and internal manifests never appear in visitor-visible text.

### Response and credential boundary

- **CP1-R13 — Credential prohibition.** Support never generates, retrieves, solicits, validates, echoes, submits, or claims to have changed passwords, OTP/TOTP values, verification or recovery codes, authenticator secrets, reset tokens, session credentials, or account-security state. No Support capability imports auth/reset execution, and no Support request calls those operations.
- **CP1-R14 — Structured draft boundary.** Every model completion is length-bounded and has exactly kind,text,sourceIds,actionIds. Keep request-bound opaque aliases, reject unknown/duplicate/stale/cross-request references and alias/canonical-ID narrative, then translate and resolve canonical sources/actions against trusted context. A valid model answer cites a supplied source; model/user bytes never supply hrefs.
- **CP1-R15 — Screening and exact reviewed recovery.** Screen every invalid draft class before sinks. After a successful single model attempt for ordinary knowledge work, discard a rejected draft. If the deterministic top-ranked source selected before the call in the pinned snapshot has an admitted exact reviewed fallback, return only those constant bytes with canonical source and trusted source-appropriate actions as ANSWER_GROUNDED. Otherwise retain REFUSE_SAFETY. No interpolation, substring rewriting, raw-body fallback, second attempt, rejected arrays or live-snapshot mixing. Case summaries and no-source/transport/degraded/human/private paths remain unchanged.
- **CP1-R16 — Canonical outcome effects.** An admitted reviewed fallback has existing grounded rating/resolution effects. REFUSE_SAFETY remains non-rateable/non-resolution. Draft rejection alone drives neither E2/E6 nor relay-unavailable status. Preserve actual model usage, spend/reservations, successful relay health and the bounded rejection diagnostic even when exact reviewed recovery succeeds. Public response shape and SQL outcome set remain unchanged.
- **CP1-R17 — One canonical sink value and preserved controls.** The replacement or accepted final text passes through the existing message cipher/redactor. The `SupportMessageCipherPort.write` return record supplies the HTTP `text`; the pre-validation completion is never persisted, returned or logged. Queue reservations, daily caps, timeouts, degraded-state handling, consent, ownership, encryption, shredding, immediate human handoff and the runtime Support model remain unchanged except for the snapshot and validated source/action adapters specified here.

### Established UI

- **CP1-R18 — API contract.** Grounded and deterministic security replies may include `sources: readonly { id; label }[]` and `actions: readonly { id; label; href }[]`. The API emits only server-resolved values and retains the existing message ID, outcome, text, escalation, case-receipt, and language behavior.
- **CP1-R19 — Two existing surfaces and stale-session recovery.** The compact widget and full `/help` desk render canonical text with React escaping, source labels as text, and actions as first-party buttons or anchors. They do not render model Markdown or HTML. Both retain EN/RO controls, keyboard focus, screen-reader labels, case access and `Talk to a human`. On the CP1-R10 409 they clear the stale persisted capability, start one fresh session and retry the current redacted request once; a second mismatch renders the existing unavailable behavior. The current status block is preserved but its label is not a CP1 pass/fail oracle because truthful status-label cleanup belongs to CP3.
- **CP1-R20 — No redesign.** CP1 adds action/source affordances inside the approved Support interface. It does not restructure the help desk, replace the widget, or change visual direction.
- **CP1-R21 — Supported disjoint preview.** CP1 preview uses one coherent repository-supported stack on ports disjoint from existing UI 3001, API 8790 and provider 8791–8796 listeners. Support feature clusters do not stop, reuse or reconfigure those services and do not own stack changes. A separate infrastructure prerequisite must prove the supported configuration and hand its preview URL/configuration to CP1 before manual acceptance.

## Acceptance criteria

- **CP1-A01 (automated):** Catalog coverage enumerates every current page route by discovered pathname and proves each is mapped or explicitly excluded; it does not pass by checking only the number 11.
- **CP1-A02 (automated):** Reject incomplete pairs, missing/stale/forged component review evidence, wrong exact hashes and invalid ratification metadata. Enumerate every actual shipped entry/language, including legacy/in-code entries, and prove canonical routes/IDs/repository metadata cannot enter any model-facing surface. Injecting one prohibited route must fail admission. Projection/fallback/catalog/review byte changes alter kbVersion.
- **CP1-A03 (automated):** New peer-reviewed EN/RO content is answerable without editing `INTENT_SIGNALS`; unreviewed content and internal source paths are absent from the model-visible/visitor-visible projection.
- **CP1-A04 (automated):** Unknown actions, external and malformed URLs, token-bearing destinations, guessed dynamic IDs, missing fragments, and signed-in-without-ownership private links resolve to no action.
- **CP1-A05 (automated and manual, both UI modes):** Each required English/Romanian Forgot password phrase produces the verified existing action. Clicking it opens only the first-party flow, with zero Support-originated credential/reset submissions. This criterion is UNVERIFIED and checkpoint-blocking until the destination is supplied.
- **CP1-A06 (automated):** Force every response-policy rejection predicate in matched EN/RO knowledge requests. Prove one model attempt and either exact admitted reviewed fallback bytes with canonical source/trusted actions or the existing REFUSE_SAFETY when fallback is absent/invalid. Rejected model bytes are absent from seal/storage/HTTP/UI/case summaries; auth/reset spies remain zero. Verify no-residual supplied values, governed operation/object scope, all human labels and canonical path forms at answer/summary sinks.
- **CP1-A07 (automated):** Cipher-return, decrypted storage and HTTP equal the accepted model answer or exact reviewed fallback/refusal. Only grounded branches have normal grounded effects; refusal has none. Rejected draft alone never triggers E2/E6 or degraded relay state. Retain actual usage and immediate explicit-human E1. Prove snapshot A recovery uses A and zero-write409 behavior remains unchanged.
- **CP1-A08 (automated):** A session created under snapshot A answers only from A while A is available. If only snapshot B is available, posting through the valid A session produces the exact 409 restart response before model/persistence, then the UI creates a B session and retries the redacted current request once. A repeated mismatch does not loop.
- **CP1-A09 (manual, full `/help` and compact widget):** In EN and RO, ask how to create a debate, what Settings contains and how JSON export works; each answer states current prerequisites/limitations and offers only reviewed sources/actions. Repeat one question in the compact widget. The existing status block may remain visible, but its product-wide wording is not evaluated until CP3.
- **CP1-A10 (regression):** Focused knowledge/catalog, response-policy, snapshot route, metrics/escalation, degraded/reservation, own-context, shredding and Support render checks pass at the exact integrated revision. Repeat a check only after a relevant change, failure or observed variance. No CP1 path adds a typecheck diagnostic.
- **CP1-A11 (preview infrastructure):** A separately reviewed infrastructure change starts the supported stack on disjoint ports, records all bound ports, and proves the pre-existing listeners remain running and untouched. Ad hoc free ports without coherent repository configuration do not satisfy this criterion.

## Explicit exclusions

Bounded prior-turn history, broad paraphrase/greeting behavior, new conversational outcomes and SQL outcome migrations belong to CP2. Topic counts, truthful service-status labels, remaining SLA/presentation cleanup, held-out real-relay evaluation, rollout and rollback evidence belong to CP3. No push, publication, or production deployment occurs in CP1.
