## 3. Doctrine — the laws this campaign fights under

All pre-existing; listed so the reviewer can check the plan against them.

1. **Vertical-slice law** (orchestrator skill §6, spine v3.4.0): slice tickets at intake; **Done = developer veto after personally testing**; sub-tickets run in parallel; one worktree per slice; merge on veto; conflicts are a managed cost at merge time; all slices done → local merge → V tests the whole → only then push.
2. **One-prompt machine.** V-facing surfaces: review handoffs, genuine blockers, V DECISIONS PACKET rows.
3. **Nobody pushes without V** (spine item 6). This plan asks for ONE scoped standing exception (V-9): the FixAgent's bot identity pushes `refs/heads/fixagent/*` only, enforced by rulesets, never `dev`, never `main`.
4. **Approval-first for anything that LANDS in `dev`** (V-1). Auto-merge (FIX-14 QUICK) stays OFF behind V's switch; the bound becomes a register row before any flip.
5. **Zone law:** no modification, import, or filesystem metadata on the W.I.P. accounts/security zone (D6, machine-checked). No user-linked identifiers and no free text in error events. `id` parameters use DECLARED KINDS, not shapes.
6. **Write-as-you-go** (COMMON §4b). Rework cap 3; round 4 = V row. Reproduce-first on every rework. Freeze law at handoff (final board comment is the last write).
7. **Launch law:** assign before launch; packet copied INTO the worktree; absolute paths verified from the seat's cwd; visible Terminal with `[launch]`/`[exit]` sentinels; watchdog fingerprints every 5 min, 20-min stagnation freeze; `SKILLS LOADED` verified by body-grep, never by the line.
8. **Delta rule for gates:** seats assert "no NEW diagnostics against the pinned baseline" (`TYPECHECK-BASELINE.md`), never "zero" on a red repo; the baseline is re-pinned in a clean worktree every time `dev` moves.
9. Every slice touching `packages/**` reports its `pnpm audit:source` `blocking` array verbatim (V-6 pending).
10. **Never fake runtime data, never touch the live dev database from a test.** The Foundry's synthetic corpus lives only inside `.test-postgres/` clusters and never leaves them.

## 7. The Foundry — the agent's own database (new slice FIX-17)

### 7.1 Why this mechanism (options measured against the schema)

| Option | Verdict | Why |
|---|---|---|
| 0 · SQLite / `pg-mem` / any emulator | **NOT VIABLE** | 171 PL/pgSQL + SQL functions and 77 trigger definitions carry business logic tests assert on (erasure barriers, ciphertext enforcement, ownership locks); `pgcrypto` in `audit_crypto_internal` (`gen_random_uuid` ×161, `digest`, `hmac`); 11 schemas + 143 `SECURITY DEFINER` clauses (109 live objects) + 13 roles; `pg_advisory_xact_lock` ×24 (the migrator itself needs it); raw SQLSTATE and `lc_messages = C` asserted by `pol03-pool-resilience.test.ts`. Nothing but real Postgres passes. (Counter-argument settled by the reviewer: a TypeScript-only RED test needs no database, so an emulator could serve SOME faults — but W2/W4 demand `pnpm test:s00`, i.e. the 34 embedded-PG files, so Option 0 as THE Foundry is dead; as an extra unit backend it is irrelevant.) |
| A · status quo: one embedded PG per test file | works, slow | 34 files × (initdb + 51 migrations), serialized (`fileParallelism: false`). Already what `pnpm test:s00` does today. |
| **B · one persistent embedded PG per worktree + template clone per test** | **RECOMMENDED** | Real PG18; zero new dependencies (`embedded-postgres@18.4.0-beta.17` installed, allow-listed in `pnpm-workspace.yaml`, proven by 34 tests); honours DR-121 so the two policy tests stay green; per-test cost falls from initdb+51 migrations to one `CREATE DATABASE … TEMPLATE` (a cluster-internal file copy); `.test-postgres/` is already gitignored and unused; two thirds of the code exists (`persistent: true` + reuse logic in `acceptance/standing-db.ts`, `reservePort()` + tmpdir teardown in `tests/support/testDatabase.ts`). **Measured by the reviewer (three runs, EMPTY one-table template):** initdb 553–944 ms, `CREATE DATABASE … TEMPLATE` clone 51–60 ms, template refuses connections after `ALLOW_CONNECTIONS false`, clone still succeeds. The 51-migration clone is measured at VS-2 acceptance. |
| C · Docker `postgres:18` / testcontainers per worktree | viable later | `startWithTestcontainers()` is fully written and dormant; but it reverses V's DR-121, turns two live tests red on purpose, needs the daemon up, and `compose.dev.yaml`'s fixed host ports are not per-worktree-safe. Right answer for a Linux CI runner, not for the agent's bench today (V-12). |
| D · a database on the live dev cluster (55432) | **FORBIDDEN** | Contradicts "its own mock database"; and `startStandingDatabase()` adopts any reachable server and MIGRATES it — the live footgun this plan fences. |
| E · copy a pre-migrated `.pgdata` directory | no | 15 such directories (67–72 MB each) already litter `acceptance/`; stale snapshots silently miss migrations (`acceptance/README.md` documents the failure). B gets the speed without the disk or the staleness. |

### 7.2 Design

- **Location:** `<worktree>/.test-postgres/` — `cluster/` (data dir), `port`, `pid`, `template.ready` (records, PER migration file, `(name, sha256(bytes))` plus the register seed version → the template rebuilds itself when a migration is added, removed, renamed OR edited in place; a file-list hash alone would miss an in-place hotfix of `0034_obs_foundation.sql`), `foundry.json` (worktree path, boot time, embedded-postgres version).
- **Boot:** `new EmbeddedPostgres({ databaseDir, port: reservePort(), persistent: true, user: "debateai", password: "foundry-only", initdbFlags/postgresFlags as in testDatabase.ts })`. Reuse-if-reachable copied from `standing-db.ts` **with the fence:** the Foundry adopts a running server ONLY if `.test-postgres/pid` is alive AND the server's `foundry.meta` table names THIS worktree path. Anything else answering on the port is refused with `FOUNDRY_REFUSES_FOREIGN_SERVER`. The standing-db hazard cannot occur here by construction.
- **Template:** `CREATE DATABASE debateai_template` → `migrate(pool)` (all migration files, lexicographic, including `0056` once PR #8 lands) → register seed (`dev-deployment-register-cli` with `MIGRATION_DATABASE_URL` pointed at the Foundry) → provision the nine development principals (`dev-database-principals` pointed at the Foundry) so every URL `validateApiEnvironment` requires to be pairwise-different (four always, two more when their features are on) can differ by role on one cluster → apply the synthetic corpus → `ALTER DATABASE debateai_template WITH is_template true ALLOW_CONNECTIONS false`.
- **Per test / per query session:** `CREATE DATABASE debateai_t_<pid>_<n> TEMPLATE debateai_template` (milliseconds), dropped at teardown. Names carry the pid: three coders in one worktree never collide. One cluster per worktree, never shared between worktrees — roles are cluster-global.
- **Seam:** `startTestDatabase()` is unchanged for its 34 callers. With `DEBATEAI_WORKTREE_DB=1` it returns a template clone from the worktree's Foundry instead of a fresh initdb; without it, today's behaviour. `selectPrototypeDatabaseMechanism()` still reports `embedded-postgres` — DR-121's tests stay green.
- **Commands** (`package.json`): `pnpm mock:up` (boot + build template if missing/stale) · `pnpm mock:down` · `pnpm mock:reset` (drop and rebuild the template) · `pnpm mock:sql "<SQL>"` (a `pg`-backed one-shot — embedded-postgres ships only `initdb`, `pg_ctl`, `postgres`; there is **no `psql`** anywhere on this Mac outside Docker) · `pnpm mock:status` (port, template hash, live clones) · `pnpm mock:url [role]` (prints a role's connection string). Every `mock:*` command reads the port ONLY from `.test-postgres/port`; none accepts a URL.
- **Synthetic corpus** (`tests/support/seed/foundry/*.sql`, produced by a deterministic generator, labelled `synthetic`): a handful of contract-shaped users / runs / publications, PLUS obs fixtures — occurrences across the capture points with real-looking fingerprints, incidents in every state, one `capture_gap`, one `agent_action` chain — so tracer, ticket and proposal queries can be integration-tested before a real fault exists. Never a copy of the dev DB; never exported outside `.test-postgres/`.
- **Fence:** any connection string whose host:port equals the compose mapping (`127.0.0.1:55432`, pinned by `deploy/dev-auth/validate-compose-postgres.mjs`) or that was not minted by `mock:url` is refused with `FOUNDRY_REFUSES_LIVE_PORT` / `FOUNDRY_REFUSES_FOREIGN_URL`.
- **FixAgent use:** the daemon runs `mock:up` in the lease worktree before the RED run; the fix worker never sees a database (patch-only, FIX-13-R03); `mock:down` after `PR_PRESENTED` or on kill; the alert carries the template hash the fix was proven against.
