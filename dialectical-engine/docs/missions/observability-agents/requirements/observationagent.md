## Q2 Detection contract

**One signal type, closed vocabulary, template-only text.** Every field below is either an enumerated code, a number, a UUID, or a timestamp. No product string (question text, error message, query text, provider payload, username, email) can enter a signal — this is the injection wall (predecessor OBS-R102/RT-21) and the privacy posture at once.

| Field | Type | Producer rule (ObservationAgent) | Consumer (V channels · FixAgent) |
|---|---|---|---|
| `seq` | bigint, monotonically increasing | assigned at journal write, mirrored to Postgres | cursor for any consumer (`WHERE seq > $last`) |
| `signal_id` | uuid | one per OPEN; a CLEARED row references it via `clears_signal_id` | notification and ticket key |
| `state` | `OPEN` \| `CLEARED` | rows are immutable; clearing appends a second row | open set = `OPEN` rows without a `CLEARED` successor (`observation.open_signal_v`) |
| `class` | enum: `INFRA_DOWN, INFRA_NOT_READY, INFRA_UNKNOWN, WORKER_LOST, STALL, QUEUE_NOT_DRAINING, NO_PROGRESS, SUSPICIOUS_SUCCESS, BLIND_PERIOD, CAPTURE_GAP, CAPTURE_NOT_WIRED, SPOOL_STRANDED, CAPACITY, THROUGHPUT_ANOMALY, PROVIDER_DEGRADED, RESTART_WITNESSED, EXPECTED_ABSENT, CERT_EXPIRY, SCHEDULE_MISSED, THRESHOLD_CHANGED, AGENT_SELF` | one detector owns each class | routing table (Q5) keys on (severity, class) |
| `component` | enum: `postgres, docker, hatchet, runner, api, ui, tls_front_door, dev_stack, provider_panel, scheduler.liveness-sweep, scheduler.settlement-watch, scheduler.replay-self-test, obs_capture, spool, host, kanban, observation_agent` | from the target manifest | names the thing in the notification title |
| `severity` | `INFO` \| `DEGRADED` \| `SEVERE` \| `FATAL` | fixed per (class, component, threshold band) in the thresholds policy | routing |
| `impact_code` | enum (vocabulary below) | chosen by the detector from the fixed table | rendered as the ONE sentence V reads |
| `first_failed_probe_at` | timestamptz | timestamp of the first probe/sample that violated the rule | V's fault→detect delta (Q3) |
| `detected_at` | timestamptz | when the consecutive/window rule became true | V's delta; FixAgent ordering |
| `evidence` | jsonb, allow-listed keys per class (numbers, enums, uuids only) | e.g. `{"probe":"http_get","target":"hatchet:/api/live","consecutive_failures":2,"threshold":2,"last_status":0}` | shown as a compact line in the digest; never in the osascript body |

| `threshold_version` | integer | the ratified thresholds row in force | audit: which numbers produced this signal |

**Delivery to the FixAgent — `observation.defect_signal_v`** (read-only view, `SELECT` granted to `debateai_obs_listener`): `seq, signal_id, detected_at, defect_kind, component, severity, run_ref, work_item_ref, evidence, impact_code, threshold_version` for rows with `suspected_defect = TRUE AND state='OPEN'`, plus the matching `CLEARED` rows. Whether the FixAgent ALSO mirrors these into `obs.occurrence` (so its `occ_seq` cursor sees them) is REQ-FIX's call and is done on the FixAgent side with its own writer role and registry code — the ObservationAgent never inserts into `obs.occurrence` (Q8 D1; it needs neither the writer role nor the RP-0 pin).

**Suspected-defect rule table (the C4 line, mechanically):**

| Detector | Condition | `suspected_defect` | `defect_kind` | Why |
|---|---|---|---|---|

| queue not draining | READY items older than T while a worker is alive | TRUE | `STALL_DETECTED` | the worker is present and not claiming |

## Q3 Latency budget

Cadences and thresholds are the v1 defaults V ratifies with OBS-01 (Q5); the budget is what the defaults guarantee. "Stored" = the journal line is fsynced (the Postgres mirror follows within 5 s when Postgres is up). "V notified" = the osascript call returned (banner visible) or the `.eml`/ticket exists.

| Class | Fault → signal stored | Stored → V notified | Total | How V measures it (two machine timestamps) |
|---|---|---|---|---|

## Q4 Standalone guarantees

- **G1 Own process, own package.** `apps/observation-agent` (workspace glob `apps/*`, `pnpm-workspace.yaml:2` — no root `package.json` edit). One long-running Node process (`node --import tsx apps/observation-agent/src/main.ts` in dev; compiled on the server). It imports nothing from `apps/api`, `apps/runner`, `apps/ui`, `packages/obs-capture` runtime code, or any zone path; an architecture test asserts the import graph.
- **G2 Own start/stop/kill.** `oactl install` (writes `~/Library/LaunchAgents/com.dialectical-engine.observation-agent.plist`, `launchctl bootstrap gui/$UID …`), `oactl start`, `oactl kill` (`launchctl bootout` + SIGTERM; process gone within 5 s, SIGKILL at 5 s), `oactl uninstall`. Killing it changes nothing in the product: no product process is a child of the agent and no product process waits on it.
- **G3 Read-only against product data.** Its Postgres role `debateai_observation_agent` holds `SELECT` on `obs.*` (same column set as `debateai_obs_watchdog`, `0034:353-357`) and on the safe views this mission adds; `INSERT/UPDATE` only inside schema `observation`; **no privilege of any kind** on `core.*`, `ledger.*`, `serve.*`, `identity.*`, `register.*`, `evaluator.*`, `hatchet` database tables. Verified by V with one query (OBS-01 acceptance step 10).
- **G4 Read-only against infrastructure.** Docker access goes through one wrapper whose argv table is frozen to `ps`, `inspect`, `stats --no-stream`, `events`, `info`, `version`, `system df`; an architecture test fails on any other literal. No `start/stop/restart/kill/rm/pause/compose` ever — phase 1 is V-in-charge (C1) and the agent proposes nothing to execute.
- **G5 Cannot take the product down — bounded overhead.** CPU ≤ 2 % of one core averaged over 5 min, RSS ≤ 150 MB, ≤ 2 Postgres connections, every product-side query under `statement_timeout = 2000 ms` on the agent's own session, probe timeouts 2 s, cadence floors (liveness ≥ 5 s, detectors ≥ 15 s, capacity ≥ 30 s), HTTP probes carry `Connection: close` and a fixed `User-Agent: dialectical-engine-observation-agent`. No probe hits an authenticated or mutating route: API → `GET /v1/session` (unauthenticated 401 is the expected answer); UI → `GET /login`; never `/v1/auth/*`, `/v1/asks`, `/v1/account*` (zone).
- **G6 Survives reboot, externally observable.** launchd `RunAtLoad` + `KeepAlive` + `ThrottleInterval 10`; liveness visible without the agent's help: `launchctl list | grep com.dialectical-engine.observation-agent` (PID), heartbeat file `${OBSERVATION_STATE_DIR}/heartbeat` mtime ≤ 15 s, `observation.heartbeat.observed_at` ≤ 15 s when Postgres is up, and the digest's daily `IMPACT_AGENT_START` line after a reboot.
- **G7 One command silences it.** `oactl mute <duration> [--component <c>]` suppresses osascript, sendmail and ticket delivery (signals, digest, status and the delivery ledger continue; deliveries record `MUTED`); `oactl unmute`. `oactl kill` is the second, total switch. The FixAgent has its own switches (C3); a combined "everything off" is REQ-SYNTH's composition, not a hidden coupling.
- **G8 Fails closed on configuration, fails open on the product.** Missing/invalid thresholds or targets ⇒ the agent exits non-zero with `OBSERVATION_THRESHOLDS_UNRESOLVED` (same shape as `readLivenessPolicy`, `packages/register/src/index.ts:136-147`); the product never notices either way.
- **G9 Journal-first storage.** Every signal and delivery is appended to `${OBSERVATION_STATE_DIR}/journal/*.jsonl` (fsync) BEFORE any Postgres write; the Postgres mirror catches up when Postgres returns. The agent's store is itself a monitored component.
- **G10 Env law.** The only `process.env` reader is `loadObservationAgentEnvironment()` appended to `packages/register/src/runtime-environment.ts` (rule `tools/orphan-audit/src/index.ts:455`; V-6 collision avoided by construction). Keys: `OBSERVATION_DATABASE_URL`, `OBSERVATION_STATE_DIR`, `OBSERVATION_TARGETS_PATH`, optional `OBSERVATION_HATCHET_TOKEN_PATH`. Everything else (targets, cadences, thresholds, channels) is validated JSON/rows, never raw env.
- **G11 Zone contact: none.** No import, read, stat, list or probe of any `zone_path_prefixes` entry (`packages/obs-capture/src/zone/manifest.ts:16-25`), no route in `mount_list` (`:36-40`), no `identity.*` grant; the D6 textual guard of the demo applies to `apps/observation-agent/**` verbatim.
- **G12 Must NOT:** fix anything · write any product table · restart, start or stop any product process or container · call a language model (no LLM anywhere in this agent — DR-179 is moot for it) · store or transmit query text, error messages, prompts, payloads, cookies, tokens, emails or user ids · read `obs.occurrence_detail` · read the `hatchet` database directly in phase 1 (Q8 D4) · read secret files other than its own env and, if V grants one, the Hatchet read token.
