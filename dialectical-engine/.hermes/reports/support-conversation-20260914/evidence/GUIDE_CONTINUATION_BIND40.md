## Efficiency investigation

The repeated cost came from contract drift at boundaries rather than difficult product logic. Path ownership, output names, hashes, runtime schemas, and browser phase state were repeatedly represented in separate handwritten files. Each copy could be internally valid while disagreeing with the executable consumer, so reviews found one mismatch at a time. Browser evidence also spent cycles rediscovering hydration, cookie overlays, nested panes, and full/compact selector differences because those conditions were not expressed as one reusable state machine.

The highest-value upgrades are:

1. Generate command contracts, operator metadata, absence manifests, and review inputs from one typed artifact graph. Paths, hashes, owners, and producer/consumer schemas should have one source of truth.
2. Run the exact final operator against controlled I/O before any paid or quota-bearing execution. The dry run should reach every intended I/O boundary and prove stop-first behavior, output ownership, child status propagation, and current contract hashes.
3. Model the UI harness as an explicit state machine: hydration ready, overlay settled, mode ready, locale ready, session preserved, response accepted, screenshot contained, and restoration complete. Each transition should emit a closed code.
4. Keep an immutable execution ledger for retained and pending rows. It should calculate session/message/model budgets, prevent duplicates, and generate the composed manifest only from successful evidence.
5. Add schema validation at artifact write and read boundaries. A small versioned schema library would have caught stale field names, missing owner paths, and mismatched runtime custody before review.
6. Produce fixed-code diagnostics from the owning process without exposing raw logs or secrets. This reduces repeated diagnosis packets while preserving privacy.
7. Turn the workflow into a single prompt-driven controller: ingest the frozen mission, compile the artifact graph, run static and controlled-I/O checks, request only necessary approvals, execute once, and seal a machine-verifiable receipt. Human review remains at product, security, and acceptance boundaries rather than plumbing boundaries.

These changes would reduce tokens by replacing repeated prose reconciliation with deterministic schema checks, and reduce elapsed time by making the final operational command reviewable and executable from the same generated contract.
