## Findings

The code was correct only after those representations agreed. A typed menu registry should hold the public label, route or fragment, audience, action disposition, article family, source location and privacy boundary. Catalog, inventory checks, article skeletons and test cases can then be generated from it.

The recovery admission boundary is safe but expensive to author against. A catalog or component change intentionally invalidates the old strict manifest, so real-corpus tests cannot pretend the draft is reviewed. Author tests needed a clearly named unadmitted fixture while separate tests proved strict rejection. The repository should provide `loadAuthorDraftCorpus()` as a test-only helper that parses exact component bytes without generating review identity, plus `assertStrictCorpusRejectsDrafts()` for the production gate. That would prevent each author from rebuilding this distinction.

Action references are request-local and ordered by matching. Adding `active-sessions` shifted the relevant reference from the first to the second action in an actual-service fixture. Tests should select the reference by canonical action ID through a shared reference-map helper instead of embedding ordinal constants. This will reduce false failures whenever an adjacent safe action is added.

Preserving a product-only patch and restoring the exact RED state worked, but it is mechanical overhead. The capture runner should accept an allowlist and snapshot the test-only state automatically, then restore the implementation patch after the expected failing run. The new index binds exact article bytes, exact body bytes, projections, fallbacks, source evidence and blank owner fields for all eight records.
