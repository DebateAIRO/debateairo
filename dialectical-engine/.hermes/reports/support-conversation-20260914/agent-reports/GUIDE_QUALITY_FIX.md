## Requested retrospective

> treat it like a murder case. I want to get a nice report on what can be done better. What we must upgrade. what repeatedly costed us tokens. how we can make the coding more efficient. How can we turn this into a one prompt machine even better.

The recurring cost was discovering semantic authority gaps through expensive live replies after deterministic checks had already passed. The system checked JSON shape, membership, credentials, and closed actions, but did not bind each material claim to its visible source or distinguish an action promise from an actionless description. That gap created repeated prompt variants, capture reruns, reviews, and literal guard patches. A second cost was evidence ambiguity: full-page screenshots captured the page without proving the newest nested-pane article. A third was changing reviewed prose before producing an exact projection/fallback review bundle, which forces a deliberate but noisy manifest transition.

The next upgrade should make the server produce a request-local answer plan before calling the model: allowed fact groups, required visible sources, allowed actions, and prohibited relationships. The completion validator should consume that plan structurally instead of growing language-specific regular expressions. The review bundle should be generated with the draft article in the same author command, then attestation should be a mechanical exact-hash copy after a separate reviewer passes it. The capture should always bind API projection, exact DOM article, nested-pane geometry, and article screenshot under one row identity.

A practical “one prompt machine” is one preflight command that derives the request plan, runs source/action/security fixtures, creates the editorial digest table, computes affected suites and live rows, and emits the capture contract. It should stop before model traffic if any deterministic layer fails. One controlled model/capture pass then tests answer quality rather than rediscovering source, action, or screenshot plumbing defects. This reduces repeated live samples and review cycles while keeping editorial and security independence.

Limits: the current patch intentionally uses a finite semantic authority binder for the proved classes; it is not a general natural-language entailment engine. The proposed structural plan is future work, not part of this commit. Forgot remains unresolved, the eval rubric remains pending, and no CP1/readiness claim is made.
