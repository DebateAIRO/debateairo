### What repeatedly cost tokens

1. **Literal recovery patches created adjacent failures.** Several rounds fixed witnessed strings while modal negation, typographic apostrophes, Romanian forms or clause order remained outside the grammar. Each round needed a new live/review packet and broad evidence refresh.
2. **The former private-context feature crossed every layer.** A picker and consent toggle looked small, but authority survived in browser storage, request fields, route policy, API classification, service ports, main wiring, a two-pool repository, tool-call evidence and eval fixtures. Planning from a UI symptom would have missed the real deletion boundary.
3. **Route coverage was mistaken for guide coverage.** Eleven cataloged routes did not prove that users could ask about Replay, Workspace, Scoring, Honesty, theme, Pricing or Settings sections. The missing unit was a meaningful-control inventory.
4. **Visible behavior and internal labels drifted apart.** Recovery could be internally classified as Forgot while returning Settings, or safely refuse credential work while suppressing valid navigation. Reviews then debated classifier names instead of user-visible text/actions/calls.
5. **Content, component, review and attestation bytes previously moved through separate handoff shapes.** Mismatched manifests caused additional correction and verification cycles even when facts were sound.
6. **The unresolved Forgot destination stayed on the critical path.** Independent work continued correctly, but repeated checks could not close the checkpoint because no testable target existed.
7. **Broad suite repetition amplified small changes.** The later discipline—focused checks after each byte change, one exact final union, one attributed typecheck—was more efficient than repeating unchanged frames.

### What to upgrade

- Make `MENU-COVERAGE.json` the reviewable source for meaningful public guide coverage. Generate catalog coverage tables and live prompt matrices from it instead of hand-maintaining parallel lists.
- Use one shared semantic request analysis for recovery predicates and private-record operations. Test class transforms and paired controls, then retain real failures as seeds.
- Treat text, actions, canonical storage bytes and observed calls as the acceptance object. Internal classifier names remain diagnostics.
- Maintain one lane manifest with exact product paths, test paths, base revision and final hashes. Editorial review consumes the same component digest table that attestation writes.
- Keep authors disjoint by file and explicitly sequence the two unavoidable `support/index.ts` changes. This reduces merge/review churn.
- Remove authority end to end. A UI deletion is incomplete while a request field, route, port, main binding or repository remains callable.
- Preserve a single final-suite array as machine data. Run it once after composition; require a new reason for every repeat.
- Resolve external dependencies at intake with a concrete artifact: the canonical Forgot URL/opener, owner, and verification source. Until then, mark it blocked rather than revisiting source searches.

### Turning the work into a better one-prompt machine

A future owner prompt should supply five structured objects with the goal:

1. `publicBoundary`: allowed model/context fields and forbidden authorities;
2. `surfaceInventory`: meaningful controls with route, action/prose/exclusion disposition and language requirements;
3. `behaviorMatrix`: positive, mixed, negated, unrelated and hostile input classes with text/action/call oracles;
4. `ownershipManifest`: exact disjoint product/test paths and sequencing collisions; and
5. `verificationManifest`: focused lane commands, one final union, typecheck baseline and manual matrix.

The orchestrator can then dispatch author, editorial, attestation and final-review packets directly from those objects. This prevents each worker from rediscovering scope and makes a single prompt executable without weakening review independence.
