# NAME_DIAG self-report

> treat it like a murder case. I want to get a nice report on what can be done better. What we must upgrade. what repeatedly costed us tokens. how we can make the coding more efficient. How can we turn this into a one prompt machine even better.

## Finding

The name failure was not a punctuation bug. The classifier accepted every spelling, but the knowledge system had no reviewed identity fact. Retrieval then treated `engine` and the `debate` prefix inside `DebateAIRO` as ordinary feature words. That produced either no source or a valid-looking citation to unrelated material. The service and response policy did exactly what their current contracts said; the missing contract was semantic scope for brand-qualified queries.

Recovery had a parallel split: intent classification sent generic recovery-link wording to Settings, while exact Forgot-password wording reached a deliberately unresolved action. The repeated destination investigation remains correct: a POST operation is not a safe navigation link.

## What cost tokens

- Product naming lived in UI metadata and disclosure copy but was absent from the reviewed knowledge corpus, so final verification exercised features without exercising the product's own identity.
- Retrieval tests proved capability reachability using concatenated labels/search terms. They did not test natural brand-only, brand-plus-feature, or brand-plus-unsupported questions.
- Approximate word matching was assessed locally, while cross-article semantic drift appeared only after loading the full bilingual corpus.
- Recovery intent and recovery destination were discussed together, delaying the independent classifier correction that can safely proceed while the destination remains unresolved.

## Upgrade path

Maintain a small reviewed product-identity record with canonical aliases and test it against the full corpus. Normalize brand aliases as query context rather than feature evidence. Require brand-qualified feature queries to select only articles attached to a matched capability, and keep unsupported branded topics at `NO_SOURCE`. Add one table-driven EN/RO suite spanning identity, named features, unsupported topics, credentials, and recovery-link intent. Generate its service probes from the production corpus and fail when the first source belongs to the wrong capability.

A stronger one-prompt workflow would accept the owner sentence, derive alias/punctuation/language variants, run classifier→context→service probes against the real reviewed corpus, print the selected capability/article lineage, and emit the exact content/runtime/test/editorial ownership split. That would have exposed this issue before a browser or model-quality investigation and avoided another broad review cycle.
