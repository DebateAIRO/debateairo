### Findings

The recurring cost was not one faulty line. It was evidence assembled in layers after execution had already started. Revision custody, corpus identity, suite membership, diagnostic attribution, browser state, and output packaging repeatedly lived in separate prose instructions. Every time one changed, an author had to rediscover which prior receipt remained authoritative. That drove repeated source reads, repeated explanations, extra lease handoffs, and several live matrices whose failures were informative but expensive.

The second cost was mixing deterministic questions with model-quality sampling. Private-record refusal, recovery intent, session language, closed action resolution, and snapshot identity are deterministic preconditions. Earlier runs sometimes discovered those conditions during or after real traffic. This harness moves them before Playwright. The model is reached only after exact branch/source/action proofs exist.

The third cost was an underspecified word: “family.” The inventory has 51 included items, 20 explicit article-plan families, 12 article IDs, and nine surfaces. A literal Cartesian product would create 80 family samples before boundary and recovery rows. The bounded interpretation here uses the plan's 20 named families and pairs dimensions: two rows per family cover both languages and both surfaces. That preserves the stated observable contract with 40 family requests instead of 80. Root then required both-surface EN/RO pairs for private and injection boundaries, producing the measured 54-row total.

### Upgrades

1. Generate a single immutable live gate after authors and reviewers finish. The gate should be machine-produced from final Git custody, inventory, attestation, suite receipt, control receipt, and runtime custody. Humans should not copy hashes into prompts.
2. Compile the matrix from a reviewed coverage manifest. The manifest should name each family, natural EN/RO prompts, allowed sources, action policy, and any safe click. The harness should reject uncovered, duplicated, or extra rows.
3. Keep deterministic preflight separate from real traffic. Run branch classification, corpus selection, action resolution, recovery polarity, receipt membership, and capture parsing once with inert data. If any fail, send zero model requests.
4. Use one capture process to own fresh profile creation, session-version gating, per-request diagnostic cursors, API/DOM comparison, screenshots, counters, and final receipt. Avoid manual steps between these operations.
5. Emit one small result index from the capture. Reports and reviewer packets should consume that index instead of rereading raw logs or recreating counts.

### Toward one-prompt execution

The orchestrator prompt can become a single instruction that names the checked packet and final gate. The worker then performs a fixed sequence: validate gate → run inert preflight → verify supported stack custody → execute the frozen matrix once → seal receipt → release lease. Every conditional branch should return a fixed failure code and stop before further traffic. Reviewers consume the same receipt and exact artifacts. This removes most conversational coordination while retaining independent authorship and review.

The remaining irreducible work is editorial and product judgment: whether each answer is useful and truthful, whether Romanian and English are equivalent, and whether an external destination such as Forgot is actually canonical. Automation can bind and display that evidence, but it should not manufacture the decision.
