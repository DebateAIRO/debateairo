## What cost time and tokens

- The supported wrapper did not terminate after direct SIGTERM. A verified process-group signal removed the app/provider processes, but the strict probe treated the intentionally reusable Docker data-plane listeners as a stop failure. The reload still succeeded without touching unrelated services.
- The harness had passed inert controls because their dependency stubs did not reproduce the exact shared-article capability tie in the real `91d` product. Final product-bound verification correctly found it, but only after lifecycle and capacity work.
- The failure code did not include the canonical row or derived action IDs. Static attribution had to join matrix order, context scoring, catalog mappings, and signed-out resolution.

4. Run the exact product-bound pre-request verifier before stopping a healthy preview. Capacity must still be fresh immediately before traffic, but deterministic matrix/product compatibility can fail earlier.
5. Keep the current one-shot contract: a failed preflight seals evidence and sends zero prompts. This prevented 54 unnecessary model requests and made the failure reproducible.
