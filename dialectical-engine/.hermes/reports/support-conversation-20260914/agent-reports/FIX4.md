## What repeatedly cost work

Three earlier corrections adjusted prompts and regex boundaries without a shared representation for credential terms, values, operations and negation. That made each live failure ambiguous and encouraged local fixes that traded false positives for false negatives. Aggregate diagnostic categories also could not identify one request’s rejected guard, so the author could only form hypotheses from a seven-request window.

The fourth correction became efficient only after ARCHCHECK and SECDELTA supplied independent source-to-sink cases. Promoting those cases directly to tests produced one meaningful RED instead of another live experiment. Temporary mutations then proved each property separately: normalized redaction, clause-local relation, negation scope, narrative-ID rejection and fixed diagnostic projection.

One additional false positive was caught after GREEN: the connector alternatives `e` and `are` matched prefixes in ordinary words such as “expire” and treated the following text as a credential value. Adding word boundaries and benign credential-state controls fixed the class before commit. This is why current-byte evidence is the final 277-test frame, not the earlier 273-test frame.

## How to improve the workflow

- Start credential work with a declared bilingual class table and source-to-sink matrix. One shared fact layer should precede redactor and output-policy changes.
- Make diagnostic observability request-isolatable before live evaluation. LIVE4 should record a log cursor, issue exactly one request, read only the new window, and mark multiple events or concurrent traffic ambiguous; a UUID by itself is not an HTTP join.
- Keep current-byte chronology explicit. Later policy edits invalidate claims that an earlier aggregate covered final bytes even when the earlier suite was broader.
- Generate the finite LIVE union from changed consumers. FIX4 adds `support-credentials.test.ts`, so LIVE4 needs at least 21 files rather than carrying forward the historical 20-file label.
- Keep failed synthetic and mutation logs immutable. They explain why the code exists and prevent a later simplification from silently restoring a confirmed defect.

## One-prompt-machine improvement

A stronger initial implementation prompt would include the closed credential vocabulary, normalized-span requirement, operation/negation examples, internal-ID policy, diagnostic serialization schema, all source-to-sink consumers, and the exact LIVE correlation protocol. That would lead the author to build the shared boundary first rather than patching producer text across multiple correction rounds. Native constrained generation or a server-owned envelope remains outside this correction because the current relay does not support the former and the latter changes the owner-approved completion contract.
