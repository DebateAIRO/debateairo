## What can be done better

The mission repeatedly paid for translating prose contracts into path lists, test unions, digest tables, and provenance rules by hand. The PLAN_P2 inventory sharply reduced ambiguity, but the implementation packet should have supplied a machine-readable component schema, final union, and receipt schema as its primary contract. Human prose should explain intent while JSON enforces membership and ownership.

The component content was initially generated to a full JSON stream, which flooded one tool response and made the useful parser failure hard to see. Generators should write the artifact directly and print only count, first/last key, and digest. Diagnostic probes should always emit a fixed category and logical key, never the full authored record or model content.

Three iterations were spent distinguishing real defects from test assumptions: sandbox `listen EPERM`, source-action ordering, and the rating route's established `200`. A standard captured fixture wrapper should label `ENVIRONMENT`, `PRODUCT`, and `EXPECTATION` failures automatically and record whether the command used inert loopback resources. That would reduce manual log rereads.

The transport interruption and lease handoff required reconstructing command state from prior summaries. Every long author session should keep one small state JSON with current commit/base, dirty paths, active command/session, lease custody, last immutable log, and next step. Updating it at each heartbeat would make recovery deterministic and cheaper.

## What repeatedly cost tokens

- Repeatedly restating the same 21-path ownership, 23/25-file union, no-live-traffic rule, and review separation in prose.
- Large command output from full generated JSON and verbose test logs when only summary frames and fixed failure categories were needed.
- Re-reading nearby test fixtures to infer established HTTP status and action ordering instead of carrying those contracts in the blueprint inventory.
- Revalidating exact scope and ticket state after transport recovery because lease/command state lived across several channels.
- Maintaining separate product, mission-evidence, editorial, and attestation path conventions without one receipt generator shared by every node.

## Upgrades

1. Make the checked packet reference one canonical machine contract containing base hash, allowed paths, required outputs, test argv, prohibited effects, and ownership leases.
2. Add repository commands such as `support:recovery:generate`, `support:recovery:lint`, and `support:evidence:receipt` so authors do not create ad hoc scripts and hash tables.
3. Make the recovery linter report only `{logicalKey, field, predicate}` and run it while generating, before writing the product file.
4. Give integration fixtures a supported wrapper that handles sandbox escalation, local listener cleanup, capture paths, and environment attribution once.
5. Encode expected response/action/rating contracts in reusable fixture builders so new tests assert the behavioral delta without copying stale route assumptions.
6. Maintain the full affected-union manifest incrementally from Git dependency data; let ATTEST and LIVE consume the same immutable JSON instead of rebuilding argv.

## A better one-prompt machine

One prompt should name the objective and approved design, then point to a frozen machine packet. The runner can verify base and scope, claim the ticket, create RED fixtures from enumerated acceptance predicates, generate and lint artifacts, run only dependency-derived affected tests, execute bounded mutants, commit exact allowed paths, and emit standardized product/evidence receipts. Editorial and security reviewers should consume the same digest table and return signed result JSON that the attestation step can copy mechanically. The model remains responsible for semantics and discrepancy resolution; orchestration, hashing, ownership, and evidence packaging become deterministic tools.
