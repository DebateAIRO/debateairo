## Findings

The largest avoidable cost came from shared-lane coordination and environment-sensitive tests. The first baseline and one late aggregate ran inside the sandbox, where the integration listener fails with `listen EPERM`; neither frame says anything about product behavior. The escalated equivalents supplied the real evidence. A single packet-level field declaring which commands require a local listener, plus the approved execution mode, would prevent both attempts.

The packet named a nine-file final suite, while the first final aggregate was assembled from nearby support suites and included the KB suite instead of `support-model` and relay reservations. The implementation remained covered, but exact packet-to-command reconciliation happened late. Future packets should provide copyable argv and an explicit ordered file array in machine-readable form; the author can then hash that array into the receipt and avoid suite drift.

The existing answer service supported a legacy unstructured mode while production now requires strict structured output. Keeping the compatibility seam allowed unrelated existing tests to stay stable, but it increased branching and typing work. CP2 should remove the legacy mode once every caller provides a snapshot lookup and `kbVersion`. That will make bounded screening unconditional in the type system as well as in production composition.

The first GREEN frame caught four concrete integration mistakes: a package-boundary import, a stale Forgot-password expectation, duplicate normalization, and a parse/validate nullability split. The feedback was useful. The cheapest improvement is to export all server-safe catalog/context/navigation APIs through the package root before distributing C1/C2 work, and to include one compile-only contract fixture in the plan.

Typecheck is already red on unrelated baseline paths. Comparing owned-path diagnostics against the immutable baseline was therefore essential. A mission helper that filters TypeScript diagnostics by allowed paths and records both the full and scoped results would reduce manual attribution and prevent a broad baseline failure from hiding a new local error.

Boundary mutations gave higher confidence than additional unchanged reruns: disabling credential screening failed three policy assertions; disabling the exact snapshot guard failed the 409 boundary assertion; bypassing the cipher-write return failed both canonical storage/HTTP assertions. This should be the default pattern for high-value invariants: one named mutant per invariant, an expected failing assertion, then one restored focused frame.
