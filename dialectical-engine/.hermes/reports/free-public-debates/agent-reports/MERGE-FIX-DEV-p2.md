## Root causes and their price

1. **The packet began with two invalid N2 paths.** The lane proved the named `tests/unit/` files did not exist. Protocol required a BLOCKED stop, ticket round-trip, packet correction, skill reload, comment reread, and a second CLAIM. Estimated cost: 4–7k tokens plus orchestration latency.

2. **The gate file encoded old expected failures.** A literal first cluster run correctly printed `CLUSTER_RED` because three suites now pass: 26/0 versus 25/1, 5/0 versus 4/1, and 14/0 versus 12/2. The first packet did authorize reported pair moves, but the executable command did not encode them. Diagnosis required reading the full log and reconstructing a probe-only comparator. Estimated cost: 2–3k tokens and one full 21-suite run.

3. **The reviewer probe lived below an excluded directory.** Direct Vitest invocation returned “No test files found.” Its own header supplied the remedy: copy it temporarily into the test tree, run it, and delete it. Estimated cost: 1k tokens. A packet-provided runnable wrapper would remove this detour.

4. **The depth oracle is intentionally broad and expensive.** Its 1,010 tests scan the shipped corpus. The combined tree introduced 20 matches from cryptographic vectors, terminator bytes, frame lengths, capacities, and spool slots. Proving every match non-depth, pinning exact site counts, and rerunning the suite consumed the largest local reasoning budget: roughly 6–9k tokens and repeated parser work.

5. **The hand-combined-hunk audit lacked a generated ledger.** Reconstructing 35 decisions from merge parents, quoting both sides, and separately accounting for 11 outside-conflict paths was mechanical but high-volume. Estimated cost: 6–8k tokens. The resulting `third-behaviour-sweep.md` and `n3-outside-conflict-paths.md` should be produced during the merge, not during review repair.

6. **One command wrapper was invoked lane-relative once.** It exited 127 before Vitest started and changed nothing. The absolute retry passed 39/39. This was avoidable noise caused by keeping probe scripts outside the command cwd.

## What nearly went wrong

- Treating the initial cluster RED as a source regression would have invited edits outside the allowed list. Reading the actual/expected pairs showed it was stale comparator data and an accepted S7 baseline.
- A broad suppression of the depth detector would have made B2 green while destroying its value. Exact full-site strings plus occurrence counters ensure source drift becomes RED.
- Leaving the derived N1 expectation alone would have preserved a tautology: the fixture and oracle could drift together. The added literal panel is independent.
- Keeping only `publicationPort.publishGeneral` in N2 would not prove construction from `input.adminPool`. The new assertions pin the causal edge.
- The original reviewer probe encoded the superseded “steering absent” policy. Re-running it unchanged would have tested the wrong product decision. Its two expectations were re-derived from V-12 first.

## Ranked upgrades

1. **Packet-check must resolve every allowed path in the assigned lane before dispatch.** Abort packet generation on a missing path and print the nearest matches. Expected saving: 4–7k tokens and one heartbeat round-trip per typo.

2. **Emit an executable, versioned gate manifest with current moved pairs already applied.** Each pair should carry its authorizing commit. Expected saving: 2–3k tokens and one cluster run.

3. **Ship reviewer probes with a wrapper that copies to an included test path, runs, and removes the copy under a trap.** Expected saving: about 1k tokens and eliminates ambiguous “no tests” output.

4. **Generate the conflict ledger at resolution time.** Record path, marker ordinal, ours quote, theirs quote, decision, and forcing test as each hunk is staged. Expected saving: 5–8k tokens in review rounds.

5. **Split corpus-detector diagnostics from its 1,000-case semantic suite.** A fast inventory command should print candidate sites and exact categories before the full run. Expected saving: 2–4k tokens per detector repair.

6. **Put one absolute verification entrypoint in every packet.** It should enforce cwd, locale, log-first output, changed-path scope, known compiler baseline, three-run cluster repetition, and READY evidence extraction. Expected saving: 3–5k tokens and removes wrapper-path mistakes.

The closest route to a one-prompt machine is not a longer prompt. It is a packet compiler that validates paths and base frame, emits runnable verification manifests, and accumulates the evidence ledger while work occurs. The prompt can then state intent; the generated artifacts carry the brittle mechanics.
