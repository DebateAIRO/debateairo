## Independent verdict on the three ticketed rows

### `F-S3D-SEPARATION-PERMUTATION-FLAKE` — **CONFIRMED**, with two corrections that make it worse than filed

The reading is right. `aucCeiling` is
`empiricalQuantile([...existingNull.auc, ...missingNull.auc], 0.99)` computed
from that run's own samples (`:2835`), and the cross-arm statistic is compared
against it at `:2991`. Under a true null the comparison rejects by construction.
The gate log settles it as noise rather than signal:

* `register`: `cross_auc=0.5469` vs ceiling `0.7559` — dead null. Medians 5700.4
  vs 5700.6 ms.
* `resend`: `cross_auc=0.7852` vs ceiling `0.7695` — over by **4 pairs out of
  256**. Medians 5700.5 vs 5699.8 ms, a 0.7 ms difference on a 5.7 s interval.
* `B3 next-window`, the **higher-powered** arm at n=32: `cross_auc=0.5459` vs
  `0.6831` — dead null. A real oracle gets *easier* to see with more samples,
  not harder.
* The direction flips between routes (`existing_nontransport_max_ms` 46.4 < 65.4
  on register, 74.0 > 41.5 on resend) and `aucSeparability` folds with
  `Math.max(auc, 1-auc)`, so direction is discarded. A genuine side channel is
  directionally consistent; this is not.

**Correction 1 — it is not "about 1 %", it is about 6 %.** There are six of these
gates per run: `auc` and `classifier` for each of two routes (`:2991`, `:2992`)
plus `nextAuc` and `nextClassifier` (`:2995`, `:2996`). Even at a nominal 1 %
each that is ≈5.9 % per run. Note the resend route breached **both** its gates
(`cross_accuracy=0.7813` vs `0.7500`); only the first is in the log because
these are hard `expect`s.

**Correction 2 — the nominal 1 % is optimistic.** `sameArmRelabelingNull`
(`:140`) resamples **with replacement** from one arm's 16 values, so left and
right groups share exact duplicates. `aucSeparability` credits ties at 0.5,
which pulls the null statistic toward 0.5 and makes the null distribution
*narrower* than the tie-free cross-arm statistic it is calibrating. The ceiling
is therefore biased **low** and the true per-gate rejection rate is above 1 %.

Ceiling untouched, as instructed — it is the security property. The file already
contains the tool for a correct decision rule: `exactPairedLabelSwapPValue`
(`:172`) is exact for n ≤ 20 and n is 16.

### `F-AUTH-MEMORY-BOUNDS-MEASURED-ON-NODE-22`, row A (`registration-database.test.ts:4237`) — **half right; it is not a leak and not a sealed bound**

`expected 3.484375 to be less than or equal to 2`. The `2` is
`tunedSecondaryPlateauCeilingMib`, a **test-local constant** inside
`s3dPlateauChildSource()` (`tests/integration/registration-database.test.ts:875`)
— it is **not** one of `packages/register/src/auth-policy.ts:100,118,470,488`.
Re-versioning the sealed register rows would not touch this row.

**It is emphatically not a leak.** The gate log's own numbers:

```
null_mib=[140.8,140.3,139.8,139.3,138.8,138.3,137.8,137.3]
plateau_spread_mib=0.094  heap_used=20.8→20.9  heap_total=22.9 flat  external=151.7 flat
waves_mib settles at 128.6 and stays there for 13 consecutive waves
```

The null samples fall **monotonically**, in a perfectly constant **0.5 MiB step**,
across all eight forced major GCs. RSS is being *returned to the OS*, not
retained. The thing the test actually guards — retention across refusal waves —
is flat at 0.094 MiB.

So the overshoot **is** consistent with a runtime change: the 2 MiB envelope was
tuned against Node 22.23.1's page-release cadence, and Node 26.8.2 releases
resident pages more aggressively after `gc({type:"major"})`. But the deeper
defect is version-independent: `nullEnvelopeMib = max - min` is a **two-sided**
spread used as a **retention** tripwire, so a monotone *decrease* trips a
detector built to catch *growth*. A re-measurement that only raised `2` would
leave that inversion in place.
