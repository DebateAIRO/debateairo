# What still needs a decision from the owner

Seven items. Every one is a place where the code and the design disagree and
somebody has to say which is real. For each I say what the website would show if
it were built, so the choice can be made by looking rather than by reading code.

### A. The canvas cards do not show who reviewed the argument — 6 rows

Right now, when one AI model checks another model's argument, the reader only
finds out by opening the details drawer. **If this were built, every argument
card on the debate canvas would carry a small coloured dot and a short label —
green "REVIEW AGREE", red "REVIEW DISPUTE", grey "REVIEW N/A" when nobody has
checked it yet — together with the name of the model that did the checking, so
you could see at a glance which parts of the debate had been cross-examined and
which had not.** This is the thing the flagship run is meant to demonstrate, and
a visitor to the site currently cannot see it. The wrinkle is the one I have to
flag: the card used to do exactly this, and a second test file added by the same
checkpoint now insists it must *not*, so you are choosing between two of your own
recorded intentions, not approving new work.

### B. The card header was split in two, and a mutation guard cannot find it — 2 rows

The block that holds the role badge, the model name and the score badges used to
be one `nodeHeader`; the checkpoint split it into a `nodeArgHeader` and a
separate `nodeScoreRow`. **Nothing about this is visible on the website — the
same things are on the card in the same order — but two guards whose whole job
is to notice if someone deletes the score badges or the model name can no longer
find the region they watch, so those deletions would now go unnoticed.** Either
the old name comes back or the guards are re-pointed at the new one; the second
is a test change, so it is yours to authorise, not mine to make.

### C. The debate page's toolbar is hidden from everyone — 1 row

The header's Library, Replay, Workspace, Honesty, Export, How-it-works and
Settings buttons are still in the page, but the checkpoint marked them
`aria-hidden` and gave them a stylesheet rule that shrinks them to a single
invisible pixel — so neither a sighted visitor nor a screen reader can reach
them. The responsive "collapse into a ⋯ menu when the window is narrow" machinery
is still in the stylesheet but now points at a name nothing uses, so it does
nothing. **If this were resolved the way the test expects, the debate page would
get its toolbar back, and on a narrow window those buttons would fold into a ⋯
overflow menu instead of overflowing the header.** I did not act because
un-hiding an entire toolbar is a visible change to the page you would want to
see first, and it is possible the reference design moved those actions somewhere
else on purpose.

### D. Three reading views name their model through a shared component now — 1 row

Thread, Split and the node drawer used to spell out the model-name line at each
place it appeared; they now call one shared `ReferenceAuthorPill` that does the
same job. **The website is unaffected — the model name and house still appear in
all three views, which I verified — but the guard that checks all eight places
still looks for the old spelling and cannot see the new one.** I fixed the one
place in this row that was a genuine loss (the Map readout had stopped naming
its model at all); the remaining three are a guard that needs re-pointing, which
is a test change and therefore yours.

### E. The debate library's counter lies, and its rows are not built to the card design — 4 rows

The "TOTAL" chip above your debate list shows the number of debates in the whole
account (41) while only four rows are on screen, and the public list shows 37
above three rows. **If this were built as designed, the chip would say "4 TOTAL"
over four rows and "3 TOTAL" over three — it would count what you can actually
see — and each library row would get the same two-layer card frame the argument
cards use, so the library and the debate page would look like one product.** The
work existed: it was written, reviewed and merged on 2026-09-01, and the merge
that brought it into the main line kept its test and threw away the change. The
decision is whether to put it back, and whether the chip means "on this page" or
"in your account", because the word TOTAL currently suggests the second.

### F. A public visitor clicking "Tree" gets a summary page, not the argument tree — 1 row

For a signed-in owner the Tree tab shows the argument canvas. For a public
visitor the checkpoint replaced that whole view with a verdict-first overview
page. **So a stranger following a shared link can read the conclusion but cannot
open the tree of arguments behind it — the thing the debate actually is.** The
test says public Tree means the canvas. Both can exist: give the overview its own
tab so a visitor lands on the summary and can still step into the tree. I did not
choose, because which one a stranger should see first is a product decision about
how the site introduces itself.

### G. The interface's own data shapes are not the shared contract, and probably should not be — 1 row

An architecture rule wants `apps/ui/lib/types.ts` to take its type definitions
from the shared `@debateai/contract` package instead of writing its own. **I
recommend not forcing this one.** The shared package has no equivalent of
`DebateDetail` at all, and the UI's version carries a dozen fields the contract
never had — branch lineage, analyzer runs, agent outputs, provenance records,
lifecycle decisions. There is a deliberate translation layer between them
(`apps/ui/lib/v3/adapter.ts`) whose entire purpose is that the two shapes differ.
Satisfying the rule would mean either pushing screen-shaped types into the
shared wire contract, which would be worse, or moving the declaration to a
different file purely so a text search stops finding it, which would be cheating.
**Nothing on the website changes either way; this is a rule that outlived its
subject, and I think the rule should be amended rather than the code bent to
it.** That is a test-file change in another seat's lane, so I am reporting it
rather than doing it.
