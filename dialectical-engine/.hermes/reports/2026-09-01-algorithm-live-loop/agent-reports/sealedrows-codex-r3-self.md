## Causes, not symptoms

1. **A deny-list was called a class guard.** The old implementation searched source; the new test bans four textual fossils of the old implementations. A fifth spelling can search the same source while retaining the imported constant and satisfying every assertion. Deletion fixed today's product path, but the test does not make that deletion durable.

3. **A legitimate non-result class was detected by an overbroad symptom.** The valid case is a stamped pre-gate token collision. v3 detects only `ABORT:` plus no applied gate, so dirty-tree and apply failures skip the checks that made them invalid in v2.
4. **The architecture concern was framed against the wrong instrument.** The 28-row audit checks workspace manifests, not `acceptance/` source imports. The edge needs a merits judgment, not an interpretation of an unrelated known-red gate.
