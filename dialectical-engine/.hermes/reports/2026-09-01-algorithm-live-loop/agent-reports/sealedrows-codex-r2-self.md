## Causes, not symptoms

1. **A character counter was called syntax-aware.** Balancing braces fixes nested object syntax only when every brace is structural. JavaScript gives braces meaning inside strings, comments, regexes, and template literals, and the anchor regex also sees commented code. The sharpest counterexample is not a false refusal but a silent success: after the real declaration is renamed, a commented old declaration can become the sole anchor and bind an unrelated prompt.
2. **Duplicated behavior was tested asymmetrically.** Happy paths exercise both extractors; refusal paths exercise only acceptance. The suite proves the copies agree on today's source, not that the development copy preserves the refusal contract.
3. **The mutation results exist, but their derivation does not.** Eight applied transcripts are admissible and the aborted attempt is honestly retained. The table that classifies them names no retained authoring program, contradicts the output of the only retained generator, and claims an expectation check without a manifest.
4. **Subtype naming is not boundary versioning.** `SealedBandCeilingRegisterRow` improves official deployment readers, but the optional base remains the live runner and derivation input. This is exactly the already-filed F-SEALEDROWS-D tail, so it informs the verdict without becoming a duplicate finding.

## What I nearly got wrong

- I nearly treated fail-loud-on-rename as sufficient. A plain rename does refuse in both copies, but adding a stale commented declaration changes the result from loud refusal to the same silent wrong-prompt success as r1.
- I nearly accepted the refusal list after seeing explicit zero/duplicate/drift tests. Searching call sites showed those tests never invoke the development twin.
- I nearly accepted the mutation index because all nine rows agree with the visible transcripts. Running the retained generator is what exposed the missing derivation: it exits 1 with one invalid transcript, and no expected manifest exists to support `ALL AS REQUIRED`.

## Checks that changed or fixed the verdict

- Four valid lexical-edge sources (`"}"`, `// }`, `/}/`, and a template literal containing `}`) made both extractors refuse before finding `criteria`.
- A commented old declaration plus a renamed real declaration made both extractors return `Unrelated system prompt naming alpha.` successfully.
- Call-site inventory in the focused test showed all negative cases invoke only `extractEvaluatorContractText`, never `extractEvaluatorContractTextDev`.
- Fresh `mutant-index.py` execution derived 7 killed / 1 survived / 1 invalid and exited 1, while the filed table says 7/1/1 NOT-RUN and `ALL AS REQUIRED`.

## Dead ends avoided

- I did not re-file the optional active type as a new finding; F-SEALEDROWS-D already owns it.
- I did not demand rename survival from another-file text scanning as the only acceptable behavior. Loud refusal would be safe; the finding is that text in comments can defeat that refusal and succeed wrongly.
- I did not reject the eight applied mutation transcripts because the aggregate index is defective. Their custody and outcomes are independently readable; the missing piece is reproducible classification and expectation checking.
- I did not rerun the full static cluster merely to recreate four already-complete artifacts. I parsed their summaries and failure names directly, then ran the focused suite and typecheck fresh.
