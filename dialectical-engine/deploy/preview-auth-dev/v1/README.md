## Package and bind the final source

Use six distinct immutable, root-owned package roots: candidate/fallback × API/UI/runner. Each root contains the full Git archive and its own installed dependency tree. Suggested roots are `/opt/debateai-v3-preview/releases/auth-dev-candidate-<id>-api` (and `-ui`, `-runner`, corresponding fallback). Do not reuse a working checkout or point a historical guard at it. `generateSourceManifest` reads the clean final Git tree, compares every archived source byte, records complete source and dependency inventories and exact PNPM/workspace link realpaths, generated contracts, native lineage/compatibility/108 bytes, provider/story/prompt and package/lock hashes. Source-root links outside that immutable package are refused. Produce one manifest per role/root, serialize it with compact `JSON.stringify` (no trailing newline) and save as root0644 under `/opt/debateai-v3-preview/artifacts/<id>/`, and retain its SHA256.

The generated source-manifest schema is now `preview-auth-dev-source-v3`; generate fresh artifacts rather than relabeling earlier receipts. Generation and verification share one layout scan and compare the exact complete dependency-root set, including missing/extra/duplicate roots. Every root must belong to a source-declared package, and the full declared link set and every subtree are verified. The exact three ignored contract outputs are separate derived inventory, described below. Only the exact `dialectical-engine/apps/ui/.next` directory in a UI-role package is delegated to the separate UI build manifest. Every other `.next` path is ordinary inventoried source. The UI build scan traverses all compiled subdirectories, including any node_modules, while retaining the no-symlink rule; PNPM/workspace links remain confined to dependency inventories.

The contract derived inventory is exactly `dialectical-engine/packages/contract/generated/{client.ts,field-inventory.json,openapi.json}`: owner, regular-file/no-link, mode0644 and complete bytes are verified; extra, missing, stale, changed-mode and redirected outputs refuse. The Git inventory still matches every tracked path exactly. Before generating a source manifest, run the existing frozen `generate:contract` producer in that immutable package. Manifest generation then verifies the frozen source and complete dependency closure and runs that unchanged producer twice in independent0700 scratch directories, copying only contract/src plus its package.json and linking only the verified original node_modules. Node26.8.2/tsx, narrow environment,60s/256KiB child bounds, complete input identities and both exact output hashes bind the proof to the shipped outputs. Scratch cleanup is unconditional. Runtime verification is read-only and never regenerates shipped files. `contractSha256` covers this exact derived inventory, also included in package-link target closure.

### runner.env recipe (names and sources only; never print a value)

On the side-by-side layout each release's runner reads its own `runner-<label>.env`, derived from the previous
release's file by `release-env.mjs derive` (it changes only `REGISTER_VERSION`, `RELEASE_KEY`, `RUNNER_WORKER_ID` and
`HATCHET_WORKER_NAME`; every other line stays byte for byte). The recipe below is for the first file it derives from.

Root `install -o root -g debateai-preview-runner -m 0640` to `/etc/debateai-v3-preview/auth-dev-v1/runner.env`. One `KEY=value` per line, no quotes, no `export`, no `$(`, no blank values; only keys of the release's `RUNNER_ENVIRONMENT_KEYS` (anything else refuses). Start from the runner's existing env file and change only these:

- Drop `NODE_EXTRA_CA_CERTS` (not a runner key; the unit sets it).
- `NODE_ENV=production` and `DEBATEAI_DEPLOYMENT_MODE=local` (exact), or `DEBATEAI_DEPLOYMENT_MODE=hosted` exactly when `api.env` says hosted (the hosted preview, `deploy/preview-release/v1/README.md` "Hosted preview with NETOPIA sandbox billing"): the API and the runner always run the same mode on the same `REGISTER_VERSION`.
- `REGISTER_VERSION`: the runner launch plan's `publication.registerVersion` (the API's selection).
- `PREVIEW_PROVIDER_TEST_CONFIG_JSON`: the exact value in the API's `api.env` (same gate socket and scope), in whichever of its three forms the API's file has ("Environment and startup": with the line-up row on the site version, the sockets-only form, and the line-up lives in the settings version).
- `PREVIEW_TEAM_USER_IDS_JSON`: the exact value in the API's `api.env`. Missing or empty refuses the runner start.
- `DATABASE_URL`: principal `debateai_prod_runner_runtime`, TLS over loopback only: host `127.0.0.1`, port 5434, database `debateai`, `sslmode=verify-full`, `sslrootcert=/etc/debateai-v3-preview/postgres-tls/ca.crt` (the preview cluster's pg_hba admits this role only as `hostssl debateai debateai_prod_runner_runtime 127.0.0.1/32 scram-sha-256`; its Unix-socket line is `local all all reject`; measured 2026-10-10). The password is the runner principal's existing one (keep it from the existing runner env file; never print it). Migration 0110 grants only to `debateai_erasure_runtime`; it changes no runner privilege.
- Keep as they are: `KEK_PATH` (the runner's own copy of the user-DEK KEK), `USER_DEK_STORE_PATH`, `CONTENT_ENCRYPTION_ENABLED`, `DEBATEAI_CUSTODY_GROUP`, `PROVIDER_REF`, `PROVIDER_DISCOVERY_TARGETS_JSON` (DeepInfra GLM, no fixture ports), `PROVIDER_PROBE_TIMEOUT_MS`, every `HATCHET_*` key, `RUNNER_WORKER_ID`, `CLAIM_MS`, `CLAIM_MARGIN_MS`, the nine `JUDGE_*`/`COMPOSER_*`/`CONFORMANCE_*` bounds, `MAX_RECOMPOSE`, `FACT_BUNDLE_VERSION`, the four `*_NUMBER_KIND`/`*_PRODUCER` keys and the five `*_CONTRACT_HASH` keys. The contract-hash keys must be present and non-empty; the runner takes its contract hashes from the sealed register, not from them, and 0110 does not touch them.

Check names only with `grep -oE '^[A-Z_][A-Z0-9_]*=' runner.env`, then the prepare-only launcher (`--plan` without `--start`) as `debateai-preview-runner`: one `preview-auth-dev-runner-prepared-v1` line means the plan, custody and environment are accepted.

### Operator checks before the first start (read-only; nothing printed is a value)

On the side-by-side layout the SAME checks of one release (and of two releases side by side) are
`release-env.mjs same --labels <label>[,<label>] --slots <slot>[,<slot>]` (prints only `OK` or `BAD` per check), and the
loaded unit is `debateai-preview-runner@<label>.service`. The checks below are the fixed-file layout's (R19 and before).

- Same preview configuration and team in both files (prints only SAME or DIFFERENT):
  `diff <(grep -E '^(PREVIEW_PROVIDER_TEST_CONFIG_JSON|PREVIEW_TEAM_USER_IDS_JSON)=' /etc/debateai-v3-preview/auth-dev-v1/api.env) <(grep -E '^(PREVIEW_PROVIDER_TEST_CONFIG_JSON|PREVIEW_TEAM_USER_IDS_JSON)=' /etc/debateai-v3-preview/auth-dev-v1/runner.env) >/dev/null && echo SAME || echo DIFFERENT`
  Repeat after every change to either file. (Code pins neither file to the other: the API cannot read runner.env and the runner cannot read api.env.)
- Same mode and register version in both files (prints only SAME or DIFFERENT):
  `diff <(grep -E '^(DEBATEAI_DEPLOYMENT_MODE|REGISTER_VERSION)=' /etc/debateai-v3-preview/auth-dev-v1/api.env | sort) <(grep -E '^(DEBATEAI_DEPLOYMENT_MODE|REGISTER_VERSION)=' /etc/debateai-v3-preview/auth-dev-v1/runner.env | sort) >/dev/null && echo SAME || echo DIFFERENT`
- The loaded unit, as systemd sees it:
  `systemctl show -p FragmentPath -p DropInPaths -p IPAddressAllow -p IPAddressDeny -p RestrictAddressFamilies debateai-preview-runner.service`
  Expected: the fragment above, exactly one drop-in (`zzzzzzzzzz-lifecycle-release.conf`), `IPAddressAllow=127.0.0.0/8 ::1/128`, `IPAddressDeny=::/0 0.0.0.0/0`, `RestrictAddressFamilies=AF_INET AF_INET6 AF_NETLINK AF_UNIX`. The prestart refuses anything else.
- What the runner can still reach on loopback: `ss -ltnH | awk '{print $4}' | sort -u`. `IPAddressAllow=localhost` admits every loopback port; it cannot filter by port. Measured 2026-10-09: 127.0.0.1:25 (Postfix), 3100 (UI), 3101 (API), 3103, 3104 and 3105 (fixtures), 5432 (a second PostgreSQL cluster), 5434 (the preview database), 17077 (Hatchet gateway, also on [::1]), 45137 (unidentified), plus 22/80/443 on all addresses and the local DNS stub on 127.0.0.53/54:53. The runner needs only the database (TLS on 127.0.0.1:5434), the Hatchet gateway and the spending gate's Unix socket. Restricting the rest by port needs a separately reviewed host firewall or cgroup egress filter; until then this list is a known gap, and the runner's database principal is pinned (`assertSelectedRunnerConnection`) so another cluster cannot be selected.
